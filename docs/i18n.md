# Internationalisation (fr / en / es)

Ce document décrit le système de traduction de l'interface, le garde-fou qui empêche d'y écrire du texte en dur, et ce
qui reste à faire. Il complète `docs/architecture.md` (couche `ui/`).

## 1. Le système

* `ui/i18n.py` : `translate(key, **values)`, `set_language(code)`, `subscribe(callback)`, et la table principale
  `_TRANSLATIONS`. Le français est la langue par défaut ; une clé inconnue s'affiche `[clé]`, une langue absente
  retombe sur le français (comportement **normal**, conservé).
* Des **modules de domaine** portent le reste des clés et sont fusionnés par `DOMAIN_TABLES` (une clé définie deux fois est
  refusée à l'import) :

  | module | contenu |
  | --- | --- |
  | `ui/i18n_hardware.py` | matériel, aperçu GPU, diagnostic copiable |
  | `ui/i18n_mograph.py` | motion graphics : calques, éditeurs, compositing, style de texte |
  | `ui/i18n_tracking.py` | tracking 2D |
  | `ui/i18n_dialogs.py` | boîtes de dialogue, filtres de fichiers, messages de la barre d'état |
  | `ui/i18n_history.py` | libellés Annuler / Rétablir (`history.*`) |
  | `ui/i18n_panels.py` | disposition, barre supérieure, rail, timeline, visionneuse, export, inspecteur, bibliothèque |
  | `ui/i18n_updates.py` | mises à jour (recherche, téléchargement vérifié, installation assistée), À propos, préférences de mise à jour |

* **Strict, sans repli silencieux** (tests et diagnostic) : `translate_strict(key, language=None, **values)` lève
  `MissingTranslationError` si la clé est inconnue, absente dans la langue demandée (pas de repli sur le français), vide,
  ou si un champ `{nom}` n'est pas fourni. `with strict_translations():` fait se comporter `translate` de cette façon
  pendant le bloc.

### Ajouter un texte

1. Choisir ou créer une clé `domaine.élément` (ASCII, minuscules) dans le module du domaine.
2. Écrire les **trois** langues, avec les **mêmes champs** `{nom}` (le test de parité refuse sinon).
3. Dans le code : `translate("domaine.clé", nom=valeur)` (ou `i18n.translate`, selon l'import déjà présent dans le module).
   Le français doit rester identique au texte d'origine quand un test le lit.
4. Une table de libellés **statique** (module ou classe) porte des **clés**, jamais le texte : on traduit à l'affichage, pas
   à l'import (sinon la langue serait figée au démarrage).
5. Jamais de logique sur le texte affiché : un libellé ne sert pas d'identifiant (voir l'identifiant de qualité de
   l'export, ou `GpuUnavailable.out_of_memory`, corrigés pour cette raison).

## 2. Le garde-fou : `tools/i18n_audit.py` et `tests/test_i18n_hardcoded.py`

Un détecteur **AST** lit `ui/` et relève :

* partout : un littéral de chaîne contenant du **français humain** (lettres accentuées ou mot d'un lexique français figé) ;
* passé **directement à un puits d'affichage** (constructeurs de widgets, `setText` / `setToolTip` / `addAction` /
  `addRow`…, `QMessageBox` / `QInputDialog` / `QFileDialog`, `showMessage`, aides d'historique) : tout texte, **quelle que
  soit sa langue**.

Sont ignorés : docstrings, journal, `ui/i18n*.py`, clés i18n, chemins, URL, formats, CSS, noms d'objets Qt, sigles et
unités, noms de langue dans leur langue, `__repr__`. Une exception légitime se marque `# i18n-ignore: raison` sur la ligne
du littéral, ou sur la ligne `def` pour une fonction entière (huit marqueurs aujourd'hui : étapes du journal d'arrêt, incrustation de
débogage, sortie du smoke test, nom par défaut du projet — donnée du cœur —, erreurs de programmation).

La **baseline** `tests/i18n_hardcoded_baseline.json` liste la dette autorisée par **fichier + texte normalisé** (espaces
repliés, champs d'une f-string en `{}`) et nombre d'occurrences, **jamais par numéro de ligne**. Le test impose un
**cliquet** : une occurrence de plus que la baseline fait échouer avec la marche à suivre ; une occurrence de moins (texte
migré) fait échouer aussi tant que l'entrée n'est pas retirée.

```
python -m tools.i18n_audit                      # = --check
python -m tools.i18n_audit --list [--zone tracking]
python -m tools.i18n_audit --summary            # chiffres par zone et par catégorie
python -m tools.i18n_audit --update-baseline    # retire ce qui a été migré (refuse tout texte neuf)
python -m tools.i18n_audit --update-baseline --accept-new   # (re)génère : à réserver à l'initialisation
python -m tools.i18n_audit --core               # inventaire des messages d'erreur du cœur (hors baseline)
```

**Limites assumées** : un texte construit à l'exécution n'est pas vu ; hors puits d'affichage, un mot français identique
à l'anglais sans accent (« Rotation », « Standard ») et un texte anglais ne sont pas détectables (ils le sont dès qu'ils
passent par un puits d'affichage).

## 3. La parité : `tests/test_i18n_parity.py`

Sur **toutes** les clés (table principale et modules de domaine) : trois langues exactement, valeurs non vides, mêmes champs, même fin de phrase
(`…`, `:`, `?`, `!`, `.`) et mêmes retours à la ligne, pas de clé répétée dans un littéral de `dict`, et **pas de français
recopié** vers l'anglais ou l'espagnol (liste blanche courte et justifiée : sigles, noms propres, emprunts, cognats ; le
test échoue aussi si une entrée de la liste devient inutile). Chaque clé est en plus résolue en mode strict dans chaque
langue.

## 4. Changement de langue à chaud

Rafraîchis sans redémarrage (abonnement à `ui.i18n`, comme `export_panel`, ou appel de `MainWindow._retranslate_ui`) :
menus et barre supérieure, rail, infobulles de raccourci, bouton lecture, visionneuse (`PreviewPanel.update_translations`),
en-têtes de piste et libellés de transition (la signature des en-têtes contient la langue), disposition (menus d'options,
fenêtres détachées : `WorkspaceManager.retranslate`), panneau Calques et bibliothèque motion graphics, inspecteur
(onglets, menu « ••• », titres de groupe, libellés de formulaire), panneau Projet et filtres, export, séquences.

Les dialogues, messages d'état et libellés d'historique sont calculés **à l'appel** : ils sont toujours dans la langue
courante, et un libellé d'historique déjà enregistré garde la langue de son enregistrement.

**Pas encore rafraîchis à chaud** (texte correct à l'ouverture dans la langue des préférences, ancien texte jusqu'à la
réouverture) : éditeur de calque graphique, compositing, style de texte, transformation avancée, étalonnage couleur (sauf
son titre), bibliothèque d'effets audio, gestionnaire de tags, tracking (déjà le cas avant ce chantier).

## 5. Dette « erreurs du cœur »

`python -m tools.i18n_audit --core` inventorie les `raise X("français…")` de `core/` : **502** messages (257
`ValueError`, 49 `KeyError`, 23 `TrackingError`, 20 `LibraryError`, 17 `UnknownLibraryItemError`, 16 `LayerError`, 12
`SequenceError`…), surtout `library_organization`, `timeline_operations`, `color_grading`, `project_io`, `project_model`,
`tracking_ops`. L'interface en affiche une partie telle quelle (`str(exc)` dans une boîte de dialogue ou
`_report_edit_refused(exc)` : une centaine de sites dans `ui/`). Ils ne sont **pas** migrés (`core/` ne connaît pas
l'interface) et des tests comparent certains de ces textes.

Mécanismes légers déjà présents : `ErrorKind` (`core/render_job.py`) traduit par `render.kind.*` ; les résultats de
tracking `code:détail` traduits par `tracking.reason.*` / `tracking.error.*` ; `SequenceIssue.kind`.

Proposition : une base d'exception `UserFacingError(ValueError)` portant `code` et `params` (données), le français restant
le message par défaut ; l'interface appelle une seule fonction `translate_exception(exc)` qui cherche `error.<code>` et
retombe sur `str(exc)`. On migre ensuite famille par famille (`SequenceError`, `TrackingError`, `LibraryError`…) sans
casser les tests, puisque `str(exc)` reste identique.
